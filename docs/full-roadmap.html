Game ⇄ Discord Communication Bridge

MERGED

Game → Discord (Announcements)

In-game announcements are forwarded to a configured Discord channel. The bot polls the adapter for new announcements at configurable intervals, deduplicates by ID, caps message length at 1800 characters, and redacts all output.

Configuration: DUNE_ANNOUNCEMENTS_ENABLED=true, DUNE_ANNOUNCEMENTS_CHANNEL=channel-id

Implementation: src/announcements.js — 7 unit tests

Discord → Game (Broadcast)

Moderator+ roles can use /dune broadcast <message> to send a message to all in-game players. The command includes:

  • Write-enabled gate (disabled by default)
  • Moderator RBAC check
  • Confirmation primitive (action, target, risk)
  • Idempotency key generation
  • 60-second per-user cooldown
  • Tamper-evident audit event
  • Message validation (1–500 printable characters)

Configuration: DUNE_DISCORD_WRITES_ENABLED=true, DISCORD_WRITE_ADMIN_ROLE_IDS

Implementation: src/broadcast.js, src/writes.js — 8 unit tests

R4.0.0+ — Highest-Risk Operations (v4.0.0+)

PLANNING • Branch: release/v4.0.0

Candidate Areas

  • Player moderation (kick, warn, ban)
  • Player messaging (whisper, broadcast, admin chat)
  • Gameplay-affecting configuration changes
  • Restore execution
  • Database-backed operations
  • Two-way chat bridge (Discord ↔ game chat)

Default Stance

  • Do not implement unless upstream exposes a narrow, audited, purpose-built adapter action
  • Do not expose raw database execution through Discord
  • Do not start with player or restore operations
  • Every action must be authorized, validated, audited, rate-limited, and reversible where practical

Required Controls

  • Owner-level authorization or equivalent
  • Out-of-band approval where practical
  • Enhanced privacy review
  • Abuse-case review
  • Audit retention expectation
  • Rollback or recovery proof
  • Incident response notes
  • Operator training or runbook update

Go/No-Go Gates

  • Any uncertain privacy, abuse, restore, or data-integrity risk blocks merge
  • Any ambiguous upstream side effect blocks merge
  • Any unresolved medium, high, or critical finding blocks merge
  • No stable release without at least one RC and owner approval
  • R3.0.0 must be merged and operational writes proven in production
