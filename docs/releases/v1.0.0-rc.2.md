prerelease adds multi-tenant architecture, canvas status cards, faction theming,
OPS observability commands, and deployment infrastructure. The bot remains

## Changes Since v1.0.0-rc.1

- Multi-tenant architecture with per-guild SQLite storage and OAuth2 setup portal
- Canvas status card rendering (1200×640 PNG, Dune Rise typeface, faction colors)
- Faction theming for embeds and status cards (Atreides, Harkonnen, Fremen)
- OPS commands (9 subcommands) with status card output
- Infra commands (`version`, `servers`, `ports`, `db`)
- Player faction system and inventory/storage commands (upstream PR pending)
- Cloudflare Tunnel for setup portal
- Cloudflare KV stats aggregation
- Git-based deployment pipeline with pre-deploy test guardrails
- Write command scaffold (12 subcommands, disabled by default)
- Fixed XSS, OAuth2 session, RBAC parsing, and embed formatting bugs
- Upstream compatibility baseline advanced to `v1.3.60`

## Security Posture

- Runtime command behavior remains read-only.
- RBAC remains restricted by default.
- The optional addon remains zero-permission.
- The bot does not mount Docker, connect to the database, read game files,
  execute shell commands, or call write-capable adapter routes.
- All setup portal HTML templates use server-side escaping for user input.
- OAuth2 state tokens stored server-side before redirect (CSRF protection).
- Multi-tenant mode isolates guild data with foreign key constraints.
- Redaction covers credentials, authorization headers, emails, SteamIDs,
  FuncomIDs, and explicit real-name fields before output reaches Discord or logs.
- No unresolved medium, high, or critical security finding is known.

## Known Limitations

- This is a prerelease candidate, not the default stable operator release.
- OPS commands return "planned" stubs until upstream wires bridge actions.
- Player inventory/storage commands require upstream PR #91 to be merged.
- No live Discord guild or live WebUI deployment test is bundled with the release.
- No write-capable commands are included (scaffolded but disabled).
- Stable `v1.0.0` promotion requires a separate release-preparation PR after
  this candidate's artifacts and validation evidence are reviewed.
