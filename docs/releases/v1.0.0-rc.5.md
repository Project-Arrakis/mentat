# Release v1.0.0-rc.5

Release date: 2026-08-10

## Summary

Fifth release candidate for the read-only `R1.0.0` production target. All 10
`ops:*` commands (`activity`, `combat`, `resources`, `economy`, `armory`,
`location`, `soc`, `prometheus`, `dashboard`, `announcements`) moved from PNG
status-card rendering to Discord embeds, backed by a new unified output
pipeline. The bot remains read-only at runtime.

**Note on how this document was produced:** this release note and the
corresponding `CHANGELOG.md` entry were not added at release time — `main`'s
git history was squashed during the project's rename to
`arrakis-control-panel`, so the granular commit-by-commit record behind the
`v1.0.0-rc.5` tag is no longer available. This document was written
retroactively (2026-08-16, closing part of issue #162's release-gate audit)
by verifying the *current* code directly against the tag, not by
reconstructing history from commit messages that no longer exist in this
clone. Where a claim below could not be independently verified against real,
current code, it is omitted rather than guessed.

## Changes Since v1.0.0-rc.3

- OPS commands render as Discord embeds instead of PNG status cards.
  `sendStatusCard()` is now used only for `server:status`; the PNG-card
  helper `sendOpsCard()` (`src/statusCard.js`) has no remaining call site.
- New unified output pipeline (`src/output/pipeline.js`,
  `src/output/enricher.js`), intended as the single call site for future
  bot responses (embed, card, error, ephemeral) in place of four previously
  independent output paths.
- `AdapterClient.parseResponseBody()` fails safe on a non-JSON 2xx response
  body (`{ ok: false, error: "Unexpected response format (...)" }`) instead
  of throwing an unhandled JSON parse error.

`v1.0.0-rc.4`'s own changes are not itemized here — its `docs/releases/`
notes file was also never created, and this session's evidence-first
verification approach did not extend to reconstructing that release's scope
without a reliable source. See the tag message
(`git show v1.0.0-rc.4 -s`) for the one-line summary that exists.

## Security Posture

- Runtime command behavior remains read-only.
- RBAC remains restricted by default.
- The optional addon remains zero-permission.
- The bot does not mount Docker, connect to the database, read game files,
  execute shell commands, or call write-capable adapter routes.
- No unresolved medium, high, or critical security finding was known at
  release time. (This changed after release: issue #167, an unauthenticated
  `POST /api/alerts/relay` endpoint, was filed 2026-08-14 and remains open as
  of this document's writing.)

## Known Limitations

- This is a prerelease candidate, not the default stable operator release.
- No write-capable commands are included (scaffolded but disabled).
- The OPS-embeds migration in this release shipped without updating the
  tests that pinned the pre-migration PNG-card behavior, leaving `main`'s CI
  red for 6 days until found and fixed under issue #162 (2026-08-16). See
  `CHANGELOG.md`'s `## Unreleased` section for the fix.
